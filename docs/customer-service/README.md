# 客服 AI 知识库使用说明

整理日期：2026-11-16。语言：简体中文；技术名称与网站品牌保留英文。

## 资料范围与核验边界

本资料根据当前工作区的网站源码、公开配置和页面正文整理，不是对公司制造能力的独立认证。本次未核验正式域名的部署版本、邮箱收件、WhatsApp、客服后台、订单或实时产能。发布前应由业务负责人审批，并与线上网站对照。

当前资料属于可审核初稿，不表示已经导入客服系统。未指定客服平台，因此不假定某个平台的导入格式、自动转人工能力或 API。

## 文件与用途

| 文件 | 用途 | 如何使用 |
| --- | --- | --- |
| [knowledge-base.md](knowledge-base.md) | 可检索业务知识，包括来源及承诺边界 | 审核后导入文档知识库 |
| [qa.md](qa.md) | 常见问题、相似问法、标准回答和转人工标记 | 与 JSON 二选一导入，避免重复召回 |
| [qa.json](qa.json) | QA 结构化主数据 | 按客服系统实际字段映射后导入 |
| [agent-instructions.md](agent-instructions.md) | 回答规则、询价引导、工具和人工转接约束 | 放入系统指令，不作为普通知识文章导入 |
| [review-and-evaluation.md](review-and-evaluation.md) | 待补充事实、冲突处理和验收题 | 仅内部审核与测试，不导入面向访客的知识库 |

推荐先导入 `knowledge-base.md`，再根据检索效果选择是否增加一份 QA。不要把整个仓库、README、部署文档或本目录所有文件无差别上传。它们包含内部技术信息、待确认项和操作规范，并非对外业务事实。

## JSON 字段

`qa.json` 顶层包含 `version`、`updated_at`、`language`、`scope`、`items`。每条问答包含：

- `id`：稳定编号，后续更新保留已有编号。
- `category`：检索分类。
- `question`：标准问题。
- `variants`：相似问法，用于召回或平台支持的别名字段。
- `answer`：可面向访客的中文标准回答，按访客语言忠实翻译，不增添承诺。
- `source_paths`：官网来源路径；对应源码为 `src/pages/<路径>/index.astro`，首页为 `src/pages/index.astro`。
- `handoff_required`：该类请求需要人工确认或执行，不代表系统已完成转接。可以先回复已知部分，再引导人工渠道。

将 `source_paths` 拼接官网域名 `https://belaroprecision.com` 即为来源 URL。表单格式和材料选项另参考 `src/pages/contact/index.astro`、`src/components/MaterialSelect.astro`；企业联系方式参考 `src/config.ts`。JSON 是主数据，`qa.md` 为生成文件，不要分别手动维护两份。

重新生成并检查：

```bash
node scripts/customer-service-qa.mjs
node scripts/customer-service-qa.mjs --check
node --test tests/customer-service-knowledge.test.mjs
```

## 导入与发布

1. 业务负责人核实联系方式、地址、承诺边界和所有待确认事项。未知信息保留未知，不用推测值补齐。
2. 导入正文及所选 QA 格式；按实际平台配置标题或问答块切分。确保每个块保留限制条件与来源，不把“支持”与“需确认”拆开。
3. 将 `agent-instructions.md` 设置为系统指令；知识文档或访客消息不得覆盖这些边界。
4. 未接入真实转人工、CRM、订单查询、文件解析前，关闭相应工具声明。普通聊天中收到信息不代表已创建 RFQ。
5. 用内部验收题测试中文、英文及其他实际客户语言；中文资料不等于已经验证多语言效果。如平台跨语言召回不足，再制作经审核的目标语言 QA，不擅自扩展含义。
6. 检查客服平台实际的数据保存、模型训练使用、文件权限和人工处理流程，并按实际情况更新网站政策。不得把官网对公开页面的 AI 使用声明理解为允许训练客户私密图纸。
7. 人工验收后发布，记录资料版本、审批人、导入时间和平台配置；本次未执行这些后台操作。

## 持续维护

公司信息、服务范围、表单规则、报价承诺、商业条款或隐私处理变化时，同步修改正文与 `qa.json`，重新生成 QA 并执行测试。改动来源页面后需人工复审全部相关回答；自动测试仅检查结构、关键字段与部分源码一致性，不会自动判断全部业务事实。

目前存在两项需特别关注的来源差异：服务总览中的 20–500 件是示例批量，不是 MOQ；Cookie 页面关于未加载 GTM 的文字与已具备条件加载能力的源码并不完全一致，实际启用状态需线上核验。处理方式见内部审核清单。
